# FrameBuffer Management

Tujuan: Memahami bagaimana libcamera mengalokasikan buffer, memetakan memori, dan mengelola lifecycle buffer selaam proses capture.

## FrameBuffer Allocation

- FrameBufferAllocator mengalokasikan buffer untuk stream.
- alloc() menghasilkan Vec<FrameBuffer>.
- buffer_count = 4 berarti tersedia empat buffer untuk digunakan bergantian, bukan hanya empat frame.
- FrameBuffer memiliki ownership yang menjaga allocator tetap hidup.

Contoh:

```rust
let mut allocator = FrameBufferAllocator::new(&cam);
let buffers = allocator.alloc(&stream).unwrap();

println!("Allocated {} buffers", buffers.len());
```

## Memory Mapping

- mmap() memetakan file descriptor ke virtual address space proses.
- MemoryMappedFrameBuffer menyediakan akses ke data buffer melalui slice.
- data() menghasilkan Vec<&[u8]>, bukan salinan Vec<u8>.
- bytes_used menunjukkan jumlah data aktual yang digunakan.
- Drop memanggil munmap() untuk melepas mapping.

Contoh:

```rust
let mapped = MemoryMappedFrameBuffer::new(buffer).unwrap();

let planes = mapped.data();
let data = planes.first().unwrap();

println!("Plane size: {} bytes", data.len());
```

## Buffer Lifecyle

Alur satu buffer:

```
Allocate
   ↓
Memory Mapping
   ↓
Attach to Request
   ↓
Queue Request
   ↓
Camera writes frame
   ↓
Request completed
   ↓
Application reads frame
   ↓
Reuse Request
   ↓
Queue Request again
```

Penting:

- Jangan membaca buffer sebelum Request selesai.
- Selesaikan penggunaan slice sebelum Request di-reuse.
- Jangan mengakses buffer yang sedang digunakan kamera.

## Buffer Reuse & Performance

- Buffer dapat digunakan berulang kali.
- ReuseFlag::REUSE_BUFFERS mempertahankan buffer yang sudah terpasang pada Request.
- Reuse menghindari alokasi buffer baru setiap frame.
- Jumlah buffer memengaruhi kemampuan pipeline menangani beberapa request sekaligus.
